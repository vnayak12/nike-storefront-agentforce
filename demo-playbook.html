Live Agent Preview

Show the agent handling real customer scenarios in Agentforce Builder

🔗 Navigate to Agentforce Builder

  1. Step 1: Open your Salesforce org and go to Setup
  2. Step 2: In Quick Find, search "Agentforce" or "Einstein Copilot"
  3. Step 3: Click Agents → find Nike CS Agent v5
  4. Step 4: Click "Open in Builder" to open the Agentforce Builder
💡 Shortcut: You can also navigate directly via the Agentforce Builder URL if you've bookmarked it.

💬 Run Demo Conversations

Click the "Preview" tab in the Builder. Use these scenarios:

🔎 Scenario A — Order Tracking
"Where is my order? My email is jane.doe@nike-test.com"
What to show: Agent looks up the customer, finds order, returns tracking info
↩️ Scenario B — Return Request
"I want to return my shoes. Order number 00000168"
What to show: Agent checks return eligibility, processes the return
⭐ Scenario C — Loyalty Status
"What's my Nike membership status? My email is jane.doe@nike-test.com"
What to show: Agent retrieves Gold tier, points balance, membership benefits
🔥 Scenario D — Escalation
"I've been waiting 3 weeks for my refund and I'm very frustrated"
What to show: Agent recognizes frustration, escalates to human agent gracefully

🧠 Talking Points During Preview

→ Point out the reasoning trace on the right panel — shows HOW the agent decided which topic/action to use

→ Highlight the guardrails — agent stays on-topic, won't answer unrelated questions

→ Show how the agent uses real Salesforce data (orders, loyalty, cases) — not canned responses

→ Mention the agent was built with declarative tools (Flows, Apex, Prompt Templates)

Agent Analytics

Tableau-powered dashboards showing agent performance at scale

🔗 Navigate to Agent Analytics

  1. Step 1: From Setup, search "Agentforce" in Quick Find
  2. Step 2: Click Agents to open the agents list
  3. Step 3: Find the Nike CS Agent and click on it
  4. Step 4: Click "Open in Builder"
  5. Step 5: In the Builder, look for the "Analytics" or "Performance" tab
💡 Alternative Path: Go to the Agentforce Studio app (App Launcher → "Agentforce Studio") and check for Analytics dashboards there. If you see an "Oops! Wrong spot" message, click "Take Me There".

📈 Key Metrics to Highlight

Deflection Rate
% of conversations resolved by the agent without human escalation
Conversation Volume
Total conversations handled — shows the 12+ test conversations we generated
Topic Breakdown
Which topics are most common (orders, returns, loyalty, escalations)
Resolution Time
Average time to resolve — typically seconds vs minutes for human agents

🗣 Talking Points

→ "This is powered by Data 360" — same analytics backbone used across Salesforce, powered by Tableau

→ "Every conversation generates analytics data" — no separate setup needed

→ "Managers can see trends over time" — identify what customers ask most, where the agent struggles

→ "This data helps optimize the agent" — natural transition to Agent Optimization demo

Agent Optimization

Deep trace view showing the AI reasoning chain behind every response

🔗 Access Agent Optimization

  1. Step 1: From the Agentforce Builder (same page as Demo 1)
  2. Step 2: Click the "Preview" tab to run a conversation
  3. Step 3: After the agent responds, look at the right-hand panel
  4. Step 4: This shows the Reasoning Trace — the full chain of AI decisions
💡 Best approach: Run one of the demo scenarios from Demo 1, then walk through the trace step by step.

🔍 What the Trace Shows

1
Topic Classification
Shows which topic the planner selected (e.g., "Order Tracking") and WHY
2
Action Selection
Which Flow/Apex action was chosen (e.g., "Lookup Order") and the input parameters
3
Data Retrieval
The actual Salesforce data returned — order records, loyalty tiers, case details
4
Response Generation
How the LLM crafted the final customer-facing response using the retrieved data

🗣 Talking Points

→ "Full transparency into AI decisions" — you can see exactly why the agent said what it said

→ "This is how you debug and improve" — if the agent picks the wrong action, you see it here

→ "Every LLM call is logged" — transitions naturally to Einstein Trust Layer

→ "No black box" — unlike generic chatbots, every step is auditable

Einstein Trust Layer

Enterprise-grade AI safety: data masking, toxicity detection, and audit trails

🔗 Navigate to Einstein Trust Layer

  1. Step 1: Go to Setup
  2. Step 2: In Quick Find, search "Einstein"
  3. Step 3: Click "Einstein Setup" (or look for "Einstein Trust Layer")
  4. Step 4: Navigate to the Trust Layer or Audit Trail section
💡 Alternative: Search for "Einstein" in Setup Quick Find — look for Trust Layer, Einstein Usage, or AI Audit Trail entries.

🛡️ Key Trust Features to Demo

🔒 Data Masking
PII (emails, phone numbers, SSNs) is automatically masked before being sent to the LLM. Show the audit log to prove sensitive data never leaves Salesforce.
🚫 Toxicity Detection
Both inputs and outputs are scanned for harmful content. The Trust Layer blocks toxic responses before they reach the customer.
📋 Audit Trail
Every LLM interaction is logged — who triggered it, what was sent, what was returned. Full compliance and governance trail.
⚡ Zero Data Retention
LLM providers don't retain or train on your data. The Trust Layer enforces this contractually and technically.

🗣 Talking Points

→ "This is THE differentiator" — no other AI platform has this level of built-in trust

→ "Your data never leaves the Trust Boundary" — PII is masked before it goes to any LLM

→ "Every AI interaction is auditable" — CIO/CISO-friendly for compliance

→ "Works automatically" — no extra configuration, it's baked into every Agentforce interaction

Testing Center

Structured test cases to validate agent behavior before going live

🔗 Navigate to Testing Center

  1. Step 1: Open the Agentforce Studio app (App Launcher → search "Agentforce Studio")
  2. Step 2: If you see an "Oops!" message, click "Take Me There"
  3. Step 3: In the left navigation, look for "Tests" or "Testing" tab
  4. Step 4: You'll see test suites you can run against the agent

🧪 What Testing Center Shows

Test Cases: Predefined customer messages with expected outcomes (topic, action, response quality)

Pass/Fail Results: Visual indicators showing which scenarios the agent handles correctly

Regression Testing: Run the same tests after making changes to ensure nothing breaks

Coverage: Shows which topics and actions are covered by test cases

🗣 Talking Points

→ "Just like unit tests for code" — structured validation for AI agents

→ "Run before every deployment" — catch issues before customers do

→ "CI/CD for AI" — testing is part of the deployment pipeline

→ "You define what 'correct' looks like" — not just vibes, measurable quality

Headless Storefront (Bonus)

Nike.com-style storefront with embedded Agentforce via headless API

🔗 Access the Storefront

  1. Step 1: Open https://nike-storefront-e6fde5597e07.herokuapp.com
  2. Step 2: Browse the Nike storefront — it's a full product catalog experience
  3. Step 3: Click the chat icon to open the Nike Assistant
  4. Step 4: Try asking about orders, returns, or products

🏗 Architecture Talking Points

→ "This uses the Messaging for In-App & Web headless API" — same Agentforce agent, completely custom UI

→ "The agent is channel-agnostic" — works in Salesforce, on your website, in your app, via API

→ "Server-side proxy handles authentication" — secure, no Salesforce credentials exposed to the browser

→ "Real-time streaming via SSE" — responses appear as the agent generates them

⚠️ Note: If the storefront chat isn't responding, use the Agentforce Builder Preview (Demo 1) as your primary demo instead. It shows the same agent with full trace visibility.

Pro Tips for a Great Demo

Make your demo unforgettable

✅ Do

→ Pre-load all tabs/pages before the demo starts

→ Start with a live conversation — it's the "wow" moment

→ Tell a story: "A customer asks about their order → agent resolves it → let's see the analytics"

→ Emphasize the Trust Layer for enterprise audiences

→ Show the trace/optimization for technical audiences

→ Have the Heroku storefront open as your "closer"

❌ Don't

→ Don't navigate to pages live during the demo (pre-load them)

→ Don't test scenarios you haven't tried before

→ Don't deep-dive into config unless audience asks

→ Don't apologize for "demo data" — frame it as "representative scenarios"

→ Don't rush through the agent conversation — let people read the responses

→ Don't skip the Trust Layer for C-suite audiences
